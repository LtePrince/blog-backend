# 后端功能设计

后端为访客提供已发布内容，为管理端提供带身份校验的写接口。判断一次改动何时对访客可见，需要分别看数据库的发布记录、内容目录中的工作稿，以及章节的已发布快照。

## 内容生命周期

| 对象 | 首次发布 | 正文修改后 | 撤销后 |
|---|---|---|---|
| 普通博客 | 登记元数据、标签、文件路径和正文 SHA-256。访客按博客 ID 阅读。 | 详情请求读取服务器上的 `index.md`，因此文件到达服务器后读者即可看到新文字。手动更新才比对正文、元数据和标签，实际变化才刷新 `updated_at`。 | 删除发布记录和标签关联，本地文件保留。 |
| 专栏 | 按专栏 slug 登记标题、简介、作者、标签及有序章节，保存各章首份正文快照。 | 专栏信息和章节可单独提交。信息调整保留各章的正文时间。 | 整栏撤销时删除章节记录和专栏标签关联。 |
| 章节 | 在已发布专栏中新增章节时，保存该章正文、哈希和时间。 | 只推送 Markdown 时访客继续读旧快照。手动更新本章时，后端校验文件内容与管理端提交的哈希；版本一致才写入。 | 撤销本章后将它从目录移除，专栏时间按剩余章节重算。 |

专栏更新时间取已发布章节更新时间的最大值，移除最新章后可以回退；空专栏为 `0`。相同正文重复发布、修改章节标题、调整目录顺序均保留已有章节的正文时间。原始字节参与哈希计算，换行变化也会改变哈希。[章节发布事务](../../internal/column/repository/chapter.go) · [专栏与章节读取](../../internal/column/repository/repository.go)

## 访客查询与可见范围

- 博客列表支持分页、标题和标签过滤。默认在分页前按更新时间倒序；旧博客缺少该值时依次回退到创建时间、文章日期。最近博客使用相同排序。专栏列表返回章节数，专栏详情返回有序目录，阅读接口返回当前章正文与前后章 slug。
- 已发布文章的正文通过内容 API 读取。`/static/` 的 GET 和 HEAD 仅开放允许类型、且由已发布内容引用的配图或博客封面。直接请求 Markdown、元数据、草稿独有图片或目录均返回 404。章节图片的引用依据是已发布快照，图片文件本身仍从磁盘读取。
- 动态读取 `moments/moments.yaml`，按日期倒序返回中英文文本；文件缺失时返回空列表。站点统计提供博客数和标签数，系统状态提供 CPU、内存和根分区使用率。

## 验收示例

同时改动已发布章节 A、B 的 Markdown，只在管理端更新 B。读取专栏目录和两章正文，应看到旧 A 和新 B，A 的 ID、哈希、更新时间保持原值，专栏时间等于 B 的新时间。再次提交相同的 B，时间应保持一致。若服务器的 B 文件仍是旧版，此次提交应失败，已发布版本应可继续阅读。[后端回归用例](../../internal/server/content_test.go) · [接口与数据结构](../implement/architecture.md)
